# pripara-arcade-mychara

캐릭터 한 명의 이름과 파츠를 선택해 **홍콩판 프리파라 마이티켓 QR**을 만드는 간소화된 웹앱입니다. GitHub Pages에 그대로 배포할 수 있습니다.

모든 작업은 브라우저에서 이루어집니다. NAS, 로그인, 세이브 파일, 모델 렌더러, 외부 API가 필요하지 않습니다. 캐릭터 이름·파츠·생성된 고유번호는 현재 브라우저에만 보관하며 서버로 전송하지 않습니다.

## 사용하기

1. 이름을 1~6자로 입력합니다. 영문 대소문자, 숫자, `! ? ★ ☆ ♪`를 사용할 수 있습니다.
2. 눈매·헤어스타일·헤어컬러·아이컬러·피부색·안경·원포인트를 선택합니다.
3. QR 만들기를 누르고 PNG로 저장합니다.

원포인트 아래의 **좋아요♥ 입력**에서 좋아요를 직접 바꿀 수 있습니다. 기본값은 20,000,000이며 0 이상의 정수를 사용합니다. 이름·파츠와 함께 이 브라우저에 저장되고, 새 QR의 좋아요와 랭크 포인트에 같은 값이 기록됩니다. 기존 플레이어 코드와 내부 UID, 플레이 횟수 초기값 1은 유지합니다.

왼쪽 아래 **처음부터 마이캐릭터 생성하기**는 제공된 고정 시작용 QR을 팝업으로 보여줍니다. **클립보드로 복사하기** 또는 **닫기**를 사용할 수 있습니다. 이 버튼은 브라우저에 저장한 현재 캐릭터를 지우지 않습니다. 고정 QR은 제공된 데이터 그대로 선명한 PNG로 재작성했으며, 일반 캐릭터 생성 QR과 별도로 사용합니다.

홍콩판 원본과 대응이 확인된 파츠만 제공합니다. 눈매와 아이컬러의 조합도 확인합니다. 의상은 기본 레슨 코디이며 별도로 선택하지 않습니다. 게임 모델을 화면에 그리지 않습니다.

같은 브라우저에서는 이름이나 파츠를 바꿔도 플레이어 코드와 내부 UID가 유지됩니다. 브라우저 데이터를 지우거나 다른 기기·브라우저·주소로 접속하면 별도 캐릭터가 됩니다. 서버에서 기기 간 계정을 공유하는 방식은 아닙니다. 플레이어 코드는 기존 에디터와 같은 `0000019` + 난수 5자리의 게임 규격이며, 서버 없이 생성하므로 다른 사용자의 코드와 전역 중복 여부를 확인하지 않습니다.

## QR에 들어가는 값

- 기존 세이브 에디터와 같은 HK App MyTicket v3, 121바이트 이진 형식
- 이름과 선택한 파츠, 기본 레슨 코디
- 입력한 좋아요(기본 20,000,000)
- 플레이 횟수 1: 게임의 첫 플레이 초기화가 지정한 캐릭터 번호를 지우지 않도록 설정
- 독립적으로 생성한 내부 UID와 0이 아닌 플레이어 식별값
- 기존 방식과 같은 2026-10-29 기록 날짜

날짜는 확인된 스탬프 기록 날짜 필드입니다. 마지막 플레이 시각이나 11:11을 저장한다고 해석하지 않습니다. 등급·생일·해금과 그 밖의 요청하지 않은 진행도는 0이며 좋아요로 등급을 추측하지 않습니다. 플레이 횟수 1은 호환을 위한 초기값이지 실제로 한 판 플레이했다는 기록이 아닙니다. 자동 대조 시험과 실제 아케이드 기기 인식은 서로 다른 검증입니다.

1.0.0에서 저장한 QR 이미지에는 플레이 횟수가 0으로 들어갑니다. 1.0.1 이상에서 **QR 만들기**를 다시 눌러 새 이미지를 저장해 주세요. 같은 브라우저에 저장된 UID와 플레이어 코드는 유지하며, 기존 PNG 파일 자체를 자동으로 수정하지는 않습니다.

## GitHub Pages 배포

자세한 순서는 [처음 배포하기](docs/처음-배포하기.md)에 있습니다.

1. GitHub Desktop의 **File → Add local repository**에서 이 프로젝트를 선택합니다.
2. **Publish repository**에서 이름을 `pripara-arcade-mychara`로 설정합니다. 무료 Pages를 이용하려면 **Keep this code private**를 해제합니다.
3. GitHub 저장소의 **Settings → Pages → Source**를 **GitHub Actions**로 선택합니다.
4. **Actions → Test and deploy MyChara to GitHub Pages → Run workflow**를 실행합니다.
5. 성공하면 **Settings → Pages → Visit site**에서 주소를 확인합니다.

이후 수정 사항을 Commit하고 **Push origin**하면 자동으로 시험한 뒤 배포합니다. 실제 GitHub 업로드 여부는 저장소에서 확인하세요. 이 프로젝트 파일을 받는 것만으로 원격 저장소가 생성되지는 않습니다.

## 개발

Node.js 24를 권장합니다. QR 생성 라이브러리를 포함했으므로 `npm install` 없이 실행할 수 있습니다.

```sh
npm test
npm run build
npm run preview
```

배포 결과는 `dist/`입니다. 로컬 미리보기는 항상 `http://127.0.0.1:8766/pripara-arcade-mychara/`를 사용합니다. 이 포트가 이미 사용 중이면 다른 포트를 열거나 기존 프로그램을 종료하지 않습니다.

GitHub에는 `vendor/`와 `public/`의 모든 파일이 포함되어야 합니다. `.gitignore`의 `/dist/`는 프로젝트 최상위 빌드 결과만 제외합니다. 업로드 전 Git에서 추적하는 파일만 내보낸 새 환경에서도 시험과 빌드가 성공하는지 확인하세요.

원본 게임 실행 파일·모델·대형 텍스처·실제 사용자 세이브·개인 QR 자료는 포함하지 않습니다. 파츠 선택용 축소 썸네일과 이름/호환 정보만 포함합니다. 관련 저작물의 권리는 각 권리자에게 있으며 비공식 호환 도구입니다. 라이브러리 출처와 라이선스는 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)를 참고하세요.
